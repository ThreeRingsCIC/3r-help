Every organisation using _Three Rings_ has at least one Core Role. You can add as many 'Core Roles' as you like, but you must always have at least one. The default Core Role is called 'Everyone'. [alert\_box type="info" class="corners"] [The blog post available here](https://www.threerings.org.uk/2015/04/23/new-feature-core-roles/)explains the theory behind Core Roles, and how they work in general. This Help page examines how to Create and Edit Core Roles, and how you can use "groups" to limit the Visibility of Core Roles to other volunteers at your organisation.[/alert\_box]

# Core Roles
When you [Add a new Role, or Edit an existing one](https://www.threerings.org.uk/help/help/admin/roles/), you have the option to make it a Core Role. Every volunter **must** have at least one Core Role, and there must always be at least one Core Role at your organisation. Like any Role, Core Roles allow you to set different levels of permissions for your volunteers. You can chose to make a number of your Roles into Core Roles to reflect the different tasks your volunteers do. Common uses for Core Roles include separating out Managers, Support Volunteers, and Trainees. Having multiple Core Roles can make it easier for complex organisations to define permissions for different groups of volunteers doing different jobs. [alert\_box type="warning" class="corners"] Remember - a volunteer can always have more than one Role, but they must have at least one Core Role - the Core Role assigns their most basic permission level, even if other Roles give them extra permissions separately.[/alert\_box]
# Directory Access
The visibility of Core Roles to other volunteers can be limited, using the 'Directory Access' feature. The only volunteers able to see members of that Core Role will be those with a Role granting them permission to do so. [alert\_box type="info" class="corners"] [The thinking behind Directory Access permissions is explained in this blog post](https://www.threerings.org.uk/2016/11/08/new-feature-groups/) which we wrote just before Milestone: Yttrium introduced Groups as a feature for the first time[/alert\_box] [Directory Access permissions for Roles are controlled from the Admin\>Roles panel](https://www.threerings.org.uk/help/help/admin/roles/) [caption id="attachment\_3370" align="aligncenter" width="502"][![Screenshot of part of a Roles table, with different levels of Directory: Access permissions for different Roles](https://www.threerings.org.uk/wp-content/uploads/2016/11/Role-table-Access-Permissions-1024x253.png)](https://www.threerings.org.uk/wp-content/uploads/2016/11/Role-table-Access-Permissions.png) This screenshot shows a Roles table for an organisation using Directory: Access to set different levels of visibility for multiple Core Roles. Click to enlarge.[/caption]
#### Assigning Visibility permissions
 To edit a Role's Directory Access level, click the `Edit` button in the Roles table. You will be given the option to set that Role's Directory Access permissions in relation to other Core Roles using the drop-down boxes. [caption id="attachment\_3371" align="aligncenter" width="500"][![Screenshot showing the Directory: Access setting page for the Trainer Role](https://www.threerings.org.uk/wp-content/uploads/2016/11/Directory-Access-Edit.png)](https://www.threerings.org.uk/wp-content/uploads/2016/11/Directory-Access-Edit.png) This screenshot shows the Trainer Role, and the drop-down panels and list of Core Roles the Trainer Role can be granted Directory: Access towards. Click to enlarge.[/caption] Each Role can be assigned one of three levels of Visibility permission in relation to a Core Role:
- `[blank]` _ie, no permissions_
- `View`
- `Manage`

If a volunteer's Roles give no Visibility of a Core Role, that volunteer will not be able to see any users with that Core Role in the Directory: while those users may appear to other volunteers, they be invisible to the users whose Role does not grant Directory Access of 'View' or higher. If a volunteer has a Role which gives View permissions on a Core Role, they will be able to see all the volunteers with that Core Role in the Directory. If a volunteer's Role grants Mange permissions on a Core Role, they will be able to Manage all the volunteers with that Core Role in the Directory. [alert\_box type="alert" class="corners"]Remember that Roles are _additive_. If a volunteer has one Role which allows them to View or Manage a particular Core Role, they will always be able to do so (even if they have another Role which does not have Directory Access View or Manage permissions)[/alert\_box]
